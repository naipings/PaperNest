# Skill Instructions

改编自 evidence-grounded-paper-deep-read（MIT，Copyright (c) 2026 MoonKirito，许可全文见同目录 LICENSE-evidence-grounded-paper-deep-read.txt）。PDF 抽取、pdffigures2 图表提取、全部图表预读与全局选图计划已在写作前由应用完成，结果随本提示提供。

每篇 PDF 输出一份独立的报告，用 What → Why → How → Experiment → Question 将论文串成一条论证路线。默认使用用户语言，中文正文建议 2800–4200 字，How 建议 1200–2000 字；复杂方法可适度超出，优先保留理解主张所必需的技术内容。

## 工作流

1. 正文已按页码和段落 ID 抽取，例如 `[Page 3, P0042]`。
2. 图和表已由 pdffigures2 提取到 Figure And Table Manifest。不得自行截图、使用其他工具裁剪，或把整页预览作为报告插图。未提取成功的图表记录为不可用；可据图注与正文作有限分析，但不能假装已经看过图片。
3. 通读主张、动机、方法、实验与局限。核对全文中的图表引用和提取清单，无法确认的引用不能当成已提取图表。
4. 写作前已逐张看图分析（All Visual Analyses），并形成全局选图计划（Global Visual Plan）：How 中技术路线与机制图去重后尽量全部展示，互补总览/局部图不视为重复；实验图按核心贡献证明链选择。依据 Report Schema 与 Reading Protocol 写五节正文。以核心贡献及其证明链为主线，图表、公式、术语在相关技术或实验处解释，不设单独的公式、创新点、背景补充或自检章节。
5. 执行全局计划，在指定章节展示并讲解所有 include=true 图表，不因压缩篇幅再次删除；不插入 include=false 图表。How 详细解释图中的技术步骤、输入输出和设计理由；实验图阐明支持的主张与证明边界。图表不凑数量。
6. 按 Quality Checklist 复核；检查过程不追加到报告正文。

## 证据与格式

重要事实须有真实页码、章节、图表号、公式号或段落锚点，例如 `(Evidence: Sec. 3.2, p. 5, P0042)`、`(Evidence: Sec. 3.2, Fig. 2)`。区分作者结论、实验观察与自己的推断；评价写明依据及可补充验证的方向。

行内公式用 `$...$`，行间公式用独占行的 `$$` 包裹。不能用其他数学定界符、代码块或反引号代替。无法可靠提取的公式应说明限制，不凭空补写。

图表提取只使用 pdffigures2；不使用 embedded-image、page-preview 或自行裁剪补图。

# Report Schema

正文只有以下五个二级章节，顺序固定。中文采用下列标题；其他语言保留 What/Why/How/Experiment/Question 和序号并翻译说明。论文标题后可加一行作者/年份/来源信息，无法确认时省略，勿添加冗长元数据表。

```markdown
# 论文精读报告：<title>

## 1. What：做了什么

## 2. Why：为什么做

## 3. How：如何实现

## 4. Experiment：如何证明有效

## 5. Question：评价与疑问
```

## 内容分工

What：用具体任务、输入输出、关键做法和贡献概括作者做了什么。贡献不能仅写“提出新框架”或“提升性能”。

Why：说明作者针对哪些既有方法、哪些条件下的不足；把作者的观察或启发与解决思路连接起来。论文未说明启发时不能虚构。

How：沿输入→表征构造→关键模块→训练/优化→推理输出详细展开技术路线。每个核心模块说明输入输出、内部操作、关键公式、设计理由及与前后模块的关系；区分训练和推理。技术路线图按全局计划去重后尽量全部展示讲解，总览图与局部机制图通常互补。图前给阅读重点，图后沿模块、箭头或坐标解释操作与设计意图。必要超参数用于解释机制，避免只列模块名称或把推理过程压成一句话。

Experiment：根据 Why 中的目的挑选实验，串起“主张→实验设计→关键结果→支持程度与边界”。说明必要的数据集、最强相关基线、指标方向和实际数值。注明比较条件；区分百分点与相对提升，显著性未报告时不得称统计显著。只挑能帮助论证的主结果、消融、泛化或成本分析，不遍历所有实验。每条实验证明链优先采用代表性图表，辅助诊断和明细通常文字引用；不同信息视角不自动等于独立核心贡献。

Question：给出有依据的独立评价。讨论影响主张的假设、遗漏、公平性、泛化或成本，区分作者自述局限与自己的疑问，提出有针对性的可验证改进，不机械套用“缺少更多数据”等泛化批评。

## 长度与证据

中文正文建议 2800–4200 字，How 建议 1200–2000 字（参考范围，不是强制截断，复杂方法可扩展）。How 和 Experiment 占主要篇幅，精简的是重复内容，不能为达成字数省略核心机制或独立方法图。少量三级标题或步骤列表可以帮助阅读；不固定每模块填写多字段表。

关键事实与数字用 `(Evidence: Sec. 3.2, Fig. 2)`、`(Evidence: p. 7, Table 1)` 或段落 ID 定位。独立判断用“我的判断”或 `(Inference from Sec. 4.1 and Table 3)`，注明推断的边界。

所有公式使用 `$...$` 或独占行的 `$$`。执行全局选图计划：方法图去重后尽量全展示，实验图按核心贡献证明链选取。只放已分析且在计划中选定的 pdffigures2 图片，写法为 `![图 2：方法流程](figures/paper-Figure2-1.png)`。不要单独建立图表或自检章节。

# Reading Protocol

先理解完整论文，再选择材料组织简洁报告；分析范围不等于报告篇幅。

## 预读

识别任务、作者主张、方法输入输出、关键假设、相关工作不足、核心机制、公式、实验条件、结论及局限。核对章节候选与页码，不能将自动索引当成已经验证的论文事实。

Figure And Table Manifest 中所有图表已完成分析；检查正文和图注的图表引用是否有遗漏，包括附录图表。无法提取的项目保留缺失记录与图注/正文分析，不自行裁剪。

## 建立论证链

围绕每个核心贡献记录“改进目标→既有不足→设计选择→对应实验→结论边界”的证据锚点。

方法按实际执行顺序阅读，注意训练与推理的区别。上下段落中的定义、假设及公式应与模块一起核实，不能只检索带 method/loss 等关键词的句子。

实验先判断它验证哪一项主张，再检查数据划分、基线配置、指标方向、提升幅度和是否报告不确定性。只挑对作者目的有解释价值的实验写入正文；没有出现某类实验不一定是缺陷，需要结合主张判断。

## 撰写与复核

依据全局选图计划中的方法图去重代表与核心贡献的图表/文字呈现理由，按五节路线写作，What 陈述贡献，Why 解释动机，How 展开技术，Experiment 建立证明链，Question 给出评价。术语和公式就地简释。

复核每项关键结论是否超过证据，每张插图是否必要，每个疑问是否有具体依据；把重复背景、同一贡献的多次展开和无关实现细节删除。

# Figure Analysis Protocol

## 提取与覆盖

图表由 pdffigures2 提取，保留 figType、name、caption、page、image、regionBoundary 等字段；page 已转换为从 1 开始的 PDF 页码。

核对提取清单、正文图表引用与附录。正文引用只能提供“可能遗漏”的线索，未人工核实不能宣称全量提取已成功。图像缺失或不可读时明确限制；不使用 embedded-image 提取、页面预览、其他裁剪工具或自行截图来替代 pdffigures2。

## 执行与讲解

所有 include=true 图表必须在计划指定章节展示并讲解，写作阶段不能再次无记录地删除。include=false 图表不插入。图表数不固定，关键是方法信息与贡献证据覆盖。

How 沿实际技术路线放图：先总览，再关键局部机制，最后训练/推理输出。图前交代阅读重点，图后结合模块、箭头、符号说明操作与设计理由，不能只有标题或“如图所示”。实验图解释关键比较、趋势及不确定性，不逐单元格复述整张表。

只使用 manifest 中的相对 image 路径。

# Quality Checklist

交付前自检，报告不追加完整性自检表。

- 正文按 What/Why/How/Experiment/Question 五节顺序。
- 贡献具体；动机指出既有方法的具体不足，并区分作者启发与推断。
- How 足够详细，可以追踪各模块输入、内部操作、输出、衔接和设计理由；训练/推理区别与必要公式就地解释。
- 实验按作者目标形成证明链，关键结果、基线与比较条件可定位。
- Question 有独立评价，区分作者局限和读者判断，并指出针对性的验证方式。
- 方法图去重后覆盖技术路线，省略图有完整覆盖其信息的代表，不能把总览和局部机制图简单当成重复。
- 核心贡献分别有代表性实验图表或具体的仅文字呈现理由；补充诊断不机械升级成核心贡献，同一证明链的追加图有必要性说明；正文执行计划，没有把独立收益全压成文字，也没有接近全量堆图。
- 插入图表来自 pdffigures2、路径存在、章节正确，图前后有具体讲解，重复内容不反复叙述。
- 行内公式使用 $...$，行间公式使用独占行的 $$；没有代码块内公式或其他数学定界符。
- 关键事实与数值有真实证据；推断未冒充作者结论，未捏造元数据、公式或实验结果。
- 删除重复背景、重复创新点、图表逐项复述、术语百科和无关复现细节。

# Terminology Explanation Protocol

只解释理解核心贡献和证明链必需的术语及公式，在 How 或 Experiment 首次使用处解释，不另设术语百科或公式章节。

术语用一两句说明含义及其在本方法中的作用；必要时指出常见混淆，例如训练与推理、相关性与因果性。

公式应与原文核对，行内用 `$...$`，行间使用：

```markdown
$$
L = L_1 + \lambda L_2
$$
```

解释核心符号、运算直觉和该式服务的设计目标即可，避免每个式子附大表。明确哪些是论文原式、哪些是等价改写或读者推导。不能可靠提取时说明证据限制，不能补写貌似合理的公式。

实验指标就地说明衡量什么、数值方向及比较条件。计算提升时注明是百分点还是相对比例。
