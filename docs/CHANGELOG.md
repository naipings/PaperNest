## 0.2.15 - 2026-08-28

### 文献调研 ReAct 深循环（Phase 7）

- 默认 `researchMode=react`：LLM 通过 function calling 自主选工具循环，结束后 Writer 写 `report.md`。
- 新增 `research_tools.rs`（SourceCollector、统一 tool 执行）；MCP 共用同一套检索工具。
- 新工具：`search_annotations`、`search_excerpts`、`update_outline`、`finish_research`。
- 设置项：`researchDepth`（quick/standard/deep）、`maxReactRounds`、`maxToolCalls`；可回退 `pipeline` 旧模式。
- 方案文档：[research-react-upgrade-plan.md](research/research-react-upgrade-plan.md)
- **JSON ReAct fallback**：弱 tool 模型在响应无 `tool_calls` 时解析 `{"action":"tool"|"finish",...}` JSON。
- **pipeline 模式**统一走 `research_tools::pipeline_invoke`，与 ReAct/MCP 共用 SourceCollector 去重。
- **Reviewer 门控**（Phase 7e）：ReAct 结束后审稿，最多 2 轮补检索。
- **子 Agent**（Phase 8）：`research_subtopic` 委派子问题，各 6 轮受限 ReAct。
- **ResearchView** 调研进行中每 1.5s 轮询步骤，`react-tool-*` 显示 label/detail 实时进度。

## 0.1.35 - 2026-08-15

### 同 PDF 第一次解析失败、第二次成功

- 根因：导入时封面提取与 LLM 正文提取各开一次 PDF.js；`destroy` 后立刻 `getDocument` 会与共享 worker 竞态（mozilla/pdf.js#16777）。第一次 LLM 常失败或半截，脏封面摘要（Abstract 粘上 Introduction）留在库里；第二次 worker 已热、分析成功，看起来像「同一文件一好一坏」。
- 现用 `pdfSession` 串行打开，导入路径 `extractForImport` 在同一次文档会话里读封面与分析文本；LLM 带 vision 失败时自动退回纯文本再试；写回优先用 LLM 字段。
- 摘要清洗在截断前对扁平文本做 small-caps 拼合（`1 I NTRODUCTION` → `1 INTRODUCTION`），封面启发式也不再把引言并进英文摘要。

### 重复确认、表格滚动与封面作者

- 重复确认根因：Tauri 能力清单只有 `dialog:allow-open/save`，`ask` 无权限会失败，论文已写入后流程中断，看起来像「没弹窗却导入成功」。现已加入 `ask/confirm/message`，并在失败时回退 `window.confirm`；导入后先按文件哈希判重，再读封面。
- 论文库表格去掉全部 `position: sticky`。WebView2 下 sticky 表头与横向滚动会拆开表头/表体；现表头与勾选列跟整表同一滚动容器，列宽仍用 `colgroup` 固定。

- 论文库用 `colgroup` 与单元格 `min/max-width` 固定列宽（对齐 TanStack table-layout:fixed 做法），勾选列保持普通文档流，横向滚动时表头与表体同步。
